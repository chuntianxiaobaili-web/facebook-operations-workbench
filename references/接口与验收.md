# Agent 接入和验收

## 接入方式

在支持本地技能目录的客户端复制整个 facebook-operations-workbench 文件夹。支持 MCP stdio 的客户端可以添加一个本地服务，命令填 node，参数填解压位置下 mcp.mjs 的绝对路径。Node 未加入 PATH 时把命令换成本机 Node 的完整路径。不同客户端如只支持远程连接，可在实际持有技能与数据的本机或云电脑上直接运行命令行。以下为本地服务配置的示例，按客户端自己的配置入口填写。

```json
{
  "mcpServers": {
    "facebook-ops": {
      "command": "node",
      "args": ["/absolute/path/facebook-operations-workbench/mcp.mjs", "--data", "/absolute/path/facebook-ops-data"]
    }
  }
}
```

桌面和 Agent 使用同一个数据目录才能看到同一账本。一个实例面向可信的本机操作员，客户代号隔离业务资产与笔记。在给互不信任的客户开放操作时使用不同系统账号或部署实例。销售工作台每个客户绑定自己的本机端口及业务名称。

在 Codex 等可直接读技能文件的环境中，指向本包 SKILL.md 即可执行。Claude Desktop 等支持 stdio 的环境使用上面的配置，连接后查看已有工具。DeepSeek Harness、WorkBuddy 或其他客户端，以该版本能否注册本地 stdio 服务或执行 Node 命令为准。云端聊天产品能否访问这台电脑取决于产品提供的连接方式。没有逐个客户端桌面验收。

## 常用输入

在本包目录运行 `node run.mjs call demo state` 可直接获得客户台账。写操作统一为 `node run.mjs call 客户代号 操作 数据.json`。JSON 文件采用 UTF-8，业务使用单独客户代号。图形界面与命令行共用台账。MCP 工具名使用 fb_ 前缀并把连字符改为下划线，参数形如 `{"tenant":"example","payload":{}}`。

| 操作 | 最小实用输入或返回 |
|---|---|
| profile | name,industry,offer,audience,identity。连接 Meta 再设 pageId,graphVersion,pageAuthorized。连接销售设 salesUrl,salesProfileName |
| group | name,url（具体群首页）,kind（own 或 third_party）,rules |
| content | surface（page、profile、group）,title,body；群稿附 groupId。主页程序稿登记 pageId,kind（post 或 reply）；回复附 postId,targetId。可记录 owner,assetRights,rightsEvidence 和来源 sourceInteractionId |
| content 再编辑 | 传同一 id。不变的稿件用 status=approved 确认，再用 status=scheduled 及带时区的 scheduledAt 排期。变更已审正文后重新批准 |
| 原生发布回执 | 已核对真实原帖后，content 传 id,status=published,remoteId,permalink，可加 receiptAt。个人身份与群发布由持有人完成 |
| interaction | externalId,text,sourceUrl,direction,channel,category,origin。强信号追加 signal=strong,evidence。交接前补充 companyKey 或已核实身份、stage=inquiry、nextAction |
| meta-check | 返回实际主页编号、名称和发帖能力。仅在具备实际操作授权后启用客户的 pageAuthorized |
| page-publish / page-reply | 传已审核稿 id。若提交后中断，应先查真实远端对象，再用 reconcileId 回读核验 |
| page-comments | postId 以及可选 after。返回 after 时还有下一页，已读取范围应保留。返回的记录默认待分类 |
| messenger-inbox | 可传 after，每页最多 10 个会话，各读最近 10 条内的入站文字。返回 partialThreads 时该会话有更早历史。附件、出站消息不进入询盘；包内支持读取与交接，私信发送由商家在收件箱处理 |
| sales-handoff / sales-sync | 传互动 id。收件方库存、价格、样品和后续报价继续用已有销售工作台处理 |
| learning / review | title,method,scope,evidence（本客户的内容或互动编号）；审阅传 id,decision（accept、reject 或 retire） |
| report / weekly | report 汇总全台账，weekly 可传含时区的 from,to，左闭右开。销售进度来源于关联证据。无观察时保持未知 |

## 跨客户代运营

主页凭证从服务进程的环境读取。租户 `demo` 对应 `FBOPS_DEMO_PAGE_TOKEN`；转大写后，连字符以 `_H` 编码，下划线以 `_U` 编码。凭证不进入客户档案、源码、截图和知识笔记。授权与版本由该客户的 Meta 应用管理员维护。多人对外服务还需按具体应用和权限取得 Meta 的对应访问级别。

选择同一企业的智能销售工作台，先启动已有销售包，在它的企业档案填业务名称，再在 Facebook 客户档案中设置 `salesUrl`（示例 http://127.0.0.1:4318）及与销售档案逐字匹配的 `salesProfileName`。出现待归属时，到销售工作台核验对应企业。已移交的信息按原消息和回执核对，避免创建重复记录。
