# v1.0.0 验收记录

本次验收使用虚构客户，运行环境为 Windows、Node.js 24.14。自动化测试 19 项全部通过，跳过 0 项。本地数据库、浏览器、Markdown 文件和智能销售工作台均实际运行。Meta 接口使用固定测试响应覆盖成功、错误和中断路径。另在全新目录按锁定的前端依赖重新构建，得到的 CSS 和 JavaScript 与交付成品逐字节一致。

| 验收项 | 已观察到的结果 |
|---|---|
| 三种渠道 | 同一客户建立公共主页稿、个人草稿和第三方群组稿。规则、审核、排期与管理员回执保存在相应渠道。原稿被修改后须重新审核 |
| 采购信号与内容 | 记录买家原话、来源、意向证据和下一步，从问题建立关联选题，重复事件按原始编号核对 |
| 真实桌面浏览器 | 在 Chrome 的 1366×900 和 390×844 两种尺寸核对界面。完成建档、群规、审稿、排期、回执、线索登记、复盘、报表和客户切换。核对 Astryx 官方 Badge 及 Neutral 主题实际生效。截图见 [虚构客户预览](../frontend/preview.png) |
| 已有销售工作台 | 在独立目录启动已有 B2B 销售服务。传真实本机 HTTP 请求，核对业务身份、消息归属与回执。重复交接得到同一消息，对应商机具有验收用成交证据后才回写成交 |
| 主页接口测试 | 使用测试响应核对身份不匹配、未到排期、并发双发、明确拒绝、结果不明、原帖与评论回复的归属。程序能回读核对并避免自动重复提交 |
| 私信读取 | 使用测试响应检查只登记发给该主页的入站文字。重复消息、缺少文本、跨主页收件人及历史截断均有对应结果 |
| Obsidian | 实际创建带种子笔记的独立客户仓库；采纳方法写入 Markdown，保留证据、适用范围、反例与审核信息。已停用的方法移入相应目录 |
| 周报与定时派发 | 周报按时间区间统计入站互动。个人稿与带附件内容留在原生任务中；本机派发器只挑选到期的公共主页纯文字帖 |
| Agent 接口 | 启动 MCP 子进程，实际完成初始化、工具枚举、客户档案写入与读取、错误请求处理；命令行和图形界面读取同一数据 |

运行全部自动化测试使用 `node --test`。若已有智能销售工作台在另一个位置，可设置环境变量 `B2B_WORKBENCH_DIR` 指向该包。独立运行且未提供销售包时，涉及该真实服务的测试会列为跳过。

**上线前的真实账号验收。** 由目标客户提供已授权主页、合适的 Graph API 版本、Page access token 和一条可用于回复的测试评论。在该客户运行 meta-check，核对身份后实发一条明确批准的文字帖，读取其原帖和评论，回复指定评论并回读，再核对周报中的两条回执。本次版本验收未向 Facebook 提交真实帖子、评论或私信。不同 Agent 客户端的界面安装和 Meta 对各客户资产授予的实际权限需在使用环境中验证。
